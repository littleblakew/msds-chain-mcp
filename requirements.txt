# mcp 2.0.0 (2026-07-28) removed `mcp.server.fastmcp`, which server.py imports, so an
# unpinned `mcp>=1.0.0` breaks the build the moment a fresh resolver runs. That is exactly
# what happened to the v1.5.3 tag: release.yml runs on ubuntu-latest (clean env → 2.0.0 →
# ModuleNotFoundError), while deploy.yml's self-hosted runner already had 1.27.0 installed
# and pip skipped the upgrade, so CI looked green and the Docker image only survived
# because the pip layer was cache-hit. Keep the ceiling until server.py is ported to 2.x.
mcp>=1.0.0,<2
httpx>=0.27.0
uvicorn>=0.30.0
starlette>=0.38.0
